# HTML Template Extraction -- Engine Amendments

Potential and implemented changes to `pipeline/html_template.py` and `pipeline/html_holdings.py`. None of the unimplemented items are blocking for current extraction (shift recovery handles misalignment, and maturity is a secondary field), but each would improve quality.

**Conventions:**
- `[IMPLEMENTED]` / `[IMPLEMENTED, LOW IMPACT]` -- already merged into the engine.
- `[LLM STEP]` -- deferred to the Phase C LLM validation step, not the programmatic engine.
- Unlabeled items are candidates still under evaluation.

**Adding a new amendment:** append to the end of this file with the next available number. Do NOT reuse numbers (see the #25 collision caveat below). When implementing an amendment, change its header to `[IMPLEMENTED]` and add a brief notes paragraph summarising the files changed and observed impact.

---

1. **`_convert_date()` -- month-name date format support.** Currently handles `MM/DD/YYYY`, `M/D/YY`, `MM/YYYY`, `YYYY-MM-DD` but NOT month-name formats like "January 2017", "June 2016", "March 2028". Returns None for these. Hercules Capital (CIK 1280784) uses this format for all 33 pre-2022 filings (~15K maturity dates lost). Fix: add a `dateutil.parser` fallback or a regex for `(January|February|...) \d{4}` -> `YYYY-MM-01`. Low risk, high coverage gain.

2. **`_select_best_variant()` / `_count_real_mismatches()` -- shift-count tiebreaker.** When two variants have the same column count but different column ORDER (e.g., both 8-col but one has Sub-Industry at logical 1 and the other has Type of Investment at logical 1), `_count_real_mismatches()` classifies ALL mismatches as "shifts" because the expected header text exists elsewhere in the concatenated header string (`expected_text in all_actual`, line 901). Both variants end up with `real=0`, `col_delta=0`, and grid-position overlap decides -- which picks the wrong variant when grid spacing varies between filings. Fix: count the number of shift-classified reasons as a separate `shift_count` and use it as a tiebreaker between `col_delta` and `gp_overlap` in `_select_best_variant()`. A variant with 0 shifts (all headers match in-place) is strictly better than one with 6 shifts. Extraction still works via shift recovery, but wrong variant means wrong `industry` source, wrong `filer_quirks` flags, etc. Affects Hercules Capital (CIK 1280784) (14 of 33 Sub-Industry filings still misassigned after template grid_positions fix; these 14 have unusual grid spacing like [0,3,5,7,9,11,15,19] where neither variant achieves good grid overlap, so shift count would be the decisive signal).

3. **HTML comparative-period separation.** `find_schedule_tables()` merges all continuation tables into one schedule, which combines current-period and comparative-period positions. FV sum ~2x XBRL for Ares Capital (CIK 1287750) ($83B vs $34B). Period separation requires either (a) detecting the "December 31, 20XX" section-header boundary between periods, or (b) matching extracted positions against XBRL ground truth to identify the current-period subset. Deferred -- not blocking for index construction since position matching handles cross-period data.

4. **`_parse_rate()` -- strip " Cash" / " PIK" suffixes before parsing.** BCP Investment Corp (CIK 1372807) and likely other filers use Interest Rate cells like "6.5% Cash", "1.0% Cash", "10.0% PIK". The engine's PIK regex handles "X% PIK" for PIK rate extraction, but `_parse_rate()` fails on "6.5% Cash" because `float("6.5% Cash")` raises ValueError. Fix: strip common suffixes (" Cash", " cash") from the rate cell before calling `float()`. Affects ~270 positions per filing (96% of rate column) for BCP Investment Corp's 2022 variant. Without this fix, rate fill drops from ~97% to ~4%.

5. **`_parse_number()` -- multi-value cell support.** Rand Capital (CIK 81955) lists multiple instruments per company in a single row, with all their cost/FV values space-separated in one cell (e.g., "1,791,278 150,000 1,791,278 150,000" for four tranches). `_parse_number()` calls `float()` which fails on the embedded spaces. Fix: after stripping `$`, commas, and parentheses, take only the first contiguous digit group (everything before the first space following a digit). E.g., "1791278 150000" -> "1791278". Low risk -- the first number is the first instrument's value, not a total. The "Total CompanyName" subtotal row (which has a single parseable number) already captures the correct company-level sum. Affects ~20 cells across Rand Capital's 41 filings. Other filers with multi-instrument rows may also benefit.

6. **`_apply_template_column_map()` -- non-empty continuation row detection.** Rand Capital (CIK 81955) splits each holding across 2-3 `<tr>` elements: row 1 has company name + date + equity%, row 2 has geographic description + cost + FV, row 3 has more description. The continuation rows have **non-empty** first cells (e.g., "Buffalo, NY. Live mobile wholesale auctions...") so `empty_first_cell` continuation detection creates separate holdings for each row. The company-name row gets no FV, and the description row gets FV but a garbage name. This is the primary cause of Rand Capital's 65% FV fill rate. Fix: add a template-configurable continuation detection mode `"continuation_detection": "missing_key_column"` with a `"continuation_key_column": N` field. A row is treated as continuation if its key column (e.g., the date column at logical index 2) is empty. New positions always have a date; continuation rows never do. The engine would merge continuation rows' FV/cost values into the preceding holding. Affects all 41 Rand Capital filings (2015+ most severely). Pattern likely exists in other small BDCs that use similar SEC filing templates.

7. **`_detect_template_drift()` -- footnote suffix in word-level header matching.** Drift detection compares header text using word-level set intersection (`set(expected.lower().split()) & set(actual.lower().split())`). When SEC filings append footnote markers directly to header words WITHOUT a space (e.g., "Cost(r)", "Units(d)", "Value(4)"), the word becomes "cost(r)" which does NOT match the template's "cost". This causes legitimate headers to be counted as mismatches. Workaround: use minimal header_text keywords that appear as standalone words in the actual header (e.g., "Par Amount" instead of "Principal/Par Amount" -- "par" and "amount" survive as words). Fix: strip parenthetical footnote markers from header words before comparison, e.g., `re.sub(r'\([^)]*\)', '', word)`. Affects CION Investment Corp (CIK 1534254) and likely other filers with footnoted headers.

8. **`_select_best_variant()` -- empty-cell grid_position bias.** When variant A's grid_positions point to the correct header cells (which may have imperfect text matches) and variant B's grid_positions point to EMPTY cells (because B's grid layout doesn't match this filing era), `_detect_template_drift()` silently skips empty cells (no mismatch counted). Variant B gets fewer "mismatches" than A despite being the wrong variant. This causes wrong variant selection when combined with amendment #7 (A's correct headers have footnote suffixes that inflate its mismatch count while B's empty cells contribute zero). Workaround: ensure the correct variant's header_text keywords survive word-level matching (see amendment #7). Fix: count skipped-because-empty fields as a weak negative signal (e.g., 0.5 per skip) so that a variant matching 6 headers with 1 mismatch beats a variant that skips 4 empty cells with 0 mismatches. Affects CION Investment Corp (CIK 1534254) where 2017+ filings were incorrectly assigned to the 2014 variant before header_text keywords were simplified.

9. **Per-filing dollar_unit override.** Template `value_formats.dollar_unit` is fixed per variant, but some filers change dollar units within a single variant's era. CION Investment Corp changed from dollars (2013-2014) to thousands (2015+). The 2014 variant covers 2014-2016 but its dollar_unit=1000 inflates 3 filings (2014) by 1000x. Auto-detection (`_detect_dollar_unit()`) correctly identifies the unit per filing, but the template's `dollar_unit` overrides it. Fix: add optional `dollar_unit_auto: true` flag to `value_formats` that defers to auto-detection when the template cannot specify a single unit for the entire variant era. Alternatively, support a `dollar_unit_by_year` map. Affects CION Investment Corp 2014 filings (~$262-418B phantom FV). Low priority -- only 3 filings affected and they're at the boundary between two eras.

10. **[IMPLEMENTED] `_apply_template_column_map()` -- alternating company/investment row merging.** Oxford Square Capital Corp (CIK 1259429) 2015-2017 format uses two rows per holding: row 1 has company name + industry (no financials), row 2 has investment description + FV/cost/principal (no company name). Both rows have non-empty first cells, so `empty_first_cell` continuation does not merge them. Fix: added `continuation_detection: "company_row_no_financials"` mode. Handles two paths: (a) company-name rows classified as section_header (single non-empty cell) are stashed and applied to the next data row inline; (b) company-name data rows (2+ non-empty cells, e.g., name + industry) are merged in a post-extraction pass. Industry from company-header rows propagates to the merged holding. Oxford Square 2015 FV fill: 53% -> 98%.

11. **[IMPLEMENTED] `_get_cell()` -- `industry` field look-ahead.** Added `"industry"` to `_NUMERIC_FIELDS` (the look-ahead set). When the INDUSTRY header is at grid N but data is at grid N+1 (common SEC HTML colspan pattern), the engine now tries `idx+1`. Guard: numeric look-ahead values are rejected for the `industry` field to prevent grabbing dollar/rate values from adjacent columns. Oxford Square 2013 industry fill: 0% -> 94% (without `grid_index` workaround).

12. **`_RATE_CELL_PATTERNS` / `_REFERENCE_MAP` -- "Base" reference rate not recognized.** Rate cells like `"14.00% (Base+ 850, 2.00% Floor)"` and `"7.75% (Base + 400, 2.00% Floor)"` fail because "Base" (meaning Prime/base rate) is absent from `_REFERENCE_MAP` and `_RATE_CELL_PATTERNS`. Fix: add `"Base": "PRIME"` and `"BASE": "PRIME"` to `_REFERENCE_MAP`, add `Base` as an alternative in patterns 1 and 4 of `_RATE_CELL_PATTERNS`, and add `Base` to `_SPREAD_CELL_PATTERN`. Affects BlackRock Capital Investment Corp (CIK 1326003) ~16 debt positions across 41 filings. Likely affects other filers that use "Base" instead of "PRIME" or "P".

13. **`_parse_rate()` / `_PIK_STRIP_RE` -- residual Cash/PIK parenthetical not cleaned.** After `_PIK_STRIP_RE` removes PIK text from `"16.00% (2.50% Cash / 13.50% PIK)"`, the result is `"16.00% (2.50% Cash / 13.50%)"`. Neither `_RATE_CELL_PATTERNS` nor `_parse_rate` can handle this residual parenthetical. Fix: in the `rate_cell_includes_reference` branch, after PIK stripping and before pattern matching, strip any remaining parenthetical content as a fallback (`re.sub(r'\(.*\)', '', cell).strip()`), then `_parse_rate("16.00%")` succeeds. Alternatively, extend `_PIK_STRIP_RE` to remove the entire `(X% Cash / Y% PIK)` parenthetical, not just the PIK portion. Affects BlackRock Capital Investment Corp (CIK 1326003) ~12 positions (SVP Worldwide Ltd.) across multiple filings. Combined with amendments #4 and #12, would bring BlackRock's debt-rate parse success from 98.4% to ~99.9%.

14. **[IMPLEMENTED] `_apply_template_column_map()` -- adaptive grid-position shifting per filing.** When a filer uses the same logical columns across many filings but the HTML grid spacing varies (e.g., maturity at grid 6 in some filings, grid 8 in others), `_get_cell()`'s +1 look-ahead cannot bridge a 2+ position gap. The existing `expected_row_width` feature handles row-width shifts (narrower continuation rows), but not column-level grid spacing differences between filings of the same variant. Current workaround: split into multiple variants with different `grid_positions` arrays (e.g., narrow_grid vs wide_grid). Fix: when `_detect_template_drift()` finds all mismatches are shifts (real=0) but gp_overlap is poor, compute a per-column delta by matching expected header text to actual header positions, then shift each field's read position accordingly. This would allow a single variant to handle multiple grid spacings without splitting. Affects BlackRock Capital Investment Corp (CIK 1326003) where 35 7-col filings split into two variants solely due to grid spacing. Also affects Rand Capital (CIK 81955) with 4+ grid layouts and Hercules Capital (CIK 1280784) with 7 grid layouts. The variant-split workaround is functional but increases template complexity and can still leave ~5-10% of filings with intermediate grid layouts partially misaligned.

Implemented in Wave 2. After grid remapping, re-checks drift and clears has_drift when only shifts remain (real==0). Files: `pipeline/html_template.py`.

15. **[LLM STEP] Embedded rate/maturity extraction from investment description text.** Several filers embed rate, maturity, and reference rate information in the company/investment description cell rather than in dedicated columns (e.g., "first lien senior secured notes, 7.44% (LIBOR + 5.00%), due 9/15/2025"). Oxford Square (CIK 1259429, 41 filings, 0% rate fill), Rand Capital (CIK 81955, 41 filings), and likely other small BDCs have this pattern across ALL eras. The programmatic engine cannot parse these because the text format varies per filer. Target for the Phase C LLM validation step: regex-extract common patterns ("X.XX%", "LIBOR/SOFR + X.XX%", "due MM/DD/YYYY") from `investment_identifier` text to populate `interest_rate`, `basis_spread`, `reference_rate_type`, and `maturity_date` fields. Expected coverage: ~60-80% of embedded rates (standard patterns), with remaining outliers requiring LLM-based parsing.

16. **`extract_filing_with_template()` -- section header row filtering.** When `instrument_in_company_cell=true` causes section-header rows to be classified as data rows rather than section headers, they are extracted as holdings with no financial data. This inflates holding counts and dilutes FV fill rates. Example: Oaktree Specialty Lending Corp (CIK 1414932) Era 1 extracts 696 holdings (should be ~241) because "Control Investments", "Affiliate Investments", and similar section headers are included as separate rows. Era 4 similarly extracts 982 holdings (should be ~500). The template's `row_conventions.section_header_examples` field identifies these patterns, but they need post-extraction filtering. Fix: after subtotal filtering (line 1275 in `extract_filing_with_template()`), add section header filtering that checks `issuer_name` against patterns from `section_header_examples` and removes matching rows. Pattern matching should be substring-based (e.g., "Control Investments" matches "Control Investments (4.9% of net assets)"). Would bring Oaktree Era 1 FV fill from 65% to ~95% and Era 4 from 69% to ~98%, while reducing row counts by ~60%. Affects filers where section headers appear as data rows with non-empty company cells.

17. **`_get_cell()` -- split-cell concatenation pattern too narrow.** The split-cell concatenation logic at line 523 uses `re.match(r"^[A-Z]+\s*\+\s*$", val)` to detect cells like "SF +" or "SOFR +" that need concatenation with the next cell's spread value. This pattern does NOT match longer reference rate codes that start with digits or contain spaces, such as "1M USD LIBOR+", "3M USD SOFR+", "6M USD LIBOR +". These are common in SEC HTML where the `<td>` for the spread column splits the reference rate text and spread number across two cells (e.g., `<td>1M USD SOFR+</td><td>3.25 %</td>`). Fix: broaden the regex to match any cell ending with a known reference rate code followed by "+", e.g., `r"^(?:.*\s)?(?:[A-Z]+|(?:\d+M\s+USD\s+(?:LIBOR|SOFR|EURIBOR)))\s*\+\s*$"`. Alternatively, match any cell whose stripped text ends with "+" after a word character. Affects Saratoga Investment Corp. (CIK 1377936) 2019+ filings (~16 filings) where `basis_spread` values are lost for all positions using split-format "NM USD SOFR+" cells. The all-in `interest_rate` from the separate "Current Rate (All In)" column is still available, so impact is limited to spread decomposition. Likely affects other BDCs that transitioned from combined "3M USD LIBOR + 3.75%" to split-cell format during the LIBOR-to-SOFR transition period (~2019-2021).

18. **`_parse_number()` -- foreign currency parenthetical stripping.** Dollar/FV cells like `"$60,919 (CAD 76,091)"`, `"26,718 (CAD 33,372)"`, `"4,455 (EUR 4,055)"` contain USD value followed by local currency equivalent in parentheses. `_parse_number()` fails because `float()` cannot parse the parenthetical text. Fix: strip parenthetical foreign currency text before parsing with `re.sub(r'\s*\([A-Z]{3}\s[\d,]+\)', '', cell)`. Alternatively, a broader `re.sub(r'\s*\([^)]*\)', '', cell)` would catch all parenthetical content but risks stripping negative-convention parentheses (already handled separately). Affects Sixth Street Specialty Lending (CIK 1508655) ~12 positions per filing across all eras (CAD, EUR, AUD, GBP denominated loans). Would increase FV fill from ~87-91% to ~95-98% for affected filings. Likely affects other BDCs with foreign currency holdings (e.g., Ares Capital, Golub Capital).

19. **[IMPLEMENTED] `find_schedule_tables()` / `extract_filing_with_template()` -- multi-entity + multi-period schedule segmentation.** When a filing is a consolidated 10-Q/10-K, the HTML can contain 3-4+ distinct schedule-of-investments sections for different entities (parent + subsidiaries) and periods (current + comparative), each with a DIFFERENT column structure. Example: Carlyle Secured Lending (CIK 1544206) filing `0001544206-18-000052` (Q2 2018 10-Q) has 4 schedule sections: (a) Credit Fund subsidiary June 30, 2018 with 8 cols incl. Interest Rate (width 20), (b) TCG BDC parent December 31, 2017 with 7 cols no Interest Rate (width 21), (c) Credit Fund sub 1 December 31, 2017 with 7 cols (width 18), (d) Credit Fund sub 2 December 31, 2017 with 7 cols (width 19). `find_schedule_tables()` merges all 4 into one "Table 0" based on header similarity. The selected variant only fits section (a), so sections (b)-(d) lose FV/rate/cost/maturity because data is shifted by 1 column and cells fall on empty positions. Worse, in some filings the actual current-period parent schedule gets dropped entirely during the merge (Carlyle's June 2018 parent schedule at HTML byte 290K-1,262K did not make it into Table 0 -- only subsidiary sections were merged). Result: 47% FV fill on affected filings. Fix options: (1) **Period/entity detection**: scan raw HTML for bolded "As of <DATE>" or "Consolidated Schedule of Investments as of <DATE>" markers and segment the merged table into period-specific + entity-specific sub-tables before variant selection. (2) **Per-row variant dispatch**: when a row's width diverges significantly from the header row width (e.g., by 2+ cells), re-match that row against other template variants (including dedicated comparative-period variants with fewer columns). (3) **Multi-section variant**: support a variant that declares multiple sub-variants dispatched by row width. Affects Carlyle Secured Lending 2 filings (2018-08 and 2018-11, both 47% FV fill). Related but distinct from amendment #3 (simple current+comparative merging): this case has additional entity-level segmentation and dropped parent schedules. Likely affects other BDC-of-BDCs or BDCs with consolidated credit fund subsidiaries (e.g., filers that use "Consolidated Schedule of Investments" wording in their 10-Q/10-K).

Implemented in Wave 4. `_segment_table_by_period()` scans for 'As of DATE' markers, segments table, extracts only the section matching report_date. Activated by `filer_quirks.segment_by_period: true`. Also added `_MONTH_DAY_YEAR_RE` for 'Month DD, YYYY' date parsing. Files: `pipeline/html_template.py`.

20. **[IMPLEMENTED] `find_schedule_tables()` -- financial-highlights table rejection heuristic.** When a filing has no HTML schedule-of-investments table (e.g., pre-2015 filings where schedules are formatted as fixed-width text inside `<P>` tags rather than HTML `<table>` elements), the engine falls back to the next most header-similar table and falsely matches against unrelated tables such as "Selected Financial Highlights" or "Per-Share Data" tables. These false matches produce 1-5 extracted holdings with null FV and drift=True. Example: Princeton Capital Corp (CIK 845385) 2014 filings `0000938047-14-000003`, `0000938047-14-000009`, `0000938047-14-000026` have no HTML schedule table; the engine picks up the per-share metrics table and extracts a single "NET ASSET VALUE, END OF PERIOD" row with 0 FV. The drift message is `expected 'investments', got 'net investment loss from operations'` -- the engine matches because "investment" appears in both strings. Fix: add a content-based validator to `find_schedule_tables()` that rejects candidate tables whose first-column values contain any of these canonical highlights-row phrases: "net investment", "net realized", "net unrealized", "total return", "ratio to", "per share", "from operations", "NAV per share", "end of period", "beginning of period", "distributions declared". Also consider requiring at least 5 data rows and at least one cell parseable as a dollar value >$100K (portfolio-scale). Low risk -- these phrases never appear as portfolio company names. Affects pre-2015 BDC filings across multiple small BDCs (Princeton Capital 3 filings; likely similar pattern in other SEC filers with pre-HTML-modernization schedules).

Implemented in Wave 3. `_is_financial_highlights()` rejects tables with >30% first-column matches against highlights phrases. Files: `pipeline/html_holdings.py`.

21. **`find_schedule_tables()` -- plain-text `<P>`-tag schedule extraction fallback.** Pre-2015 BDC filings (approximately 2013-2014) commonly use `<P>` tags with Courier/monospace font to format schedules as fixed-width plain text rather than HTML `<table>` elements. `find_schedule_tables()` only inspects `<table>` elements and returns zero candidates for these filings. Combined with amendment #20 (which would suppress false matches), the engine would return 0 holdings for these filings. Example: Princeton Capital Corp (CIK 845385) 2013 filings `0000938047-13-000008`, `0000938047-13-000010`, `0000938047-13-000017`, `0000938047-13-000021`, and 2014 filing `0000938047-14-000002` contain full schedules-of-investments as fixed-width text. Fix: add a `find_text_schedules()` helper that scans `<P>` and `<pre>` blocks for header-like text ("Portfolio Company", "Fair Value", etc.) followed by data rows aligned on whitespace boundaries. Parse using column-position detection -- identify column start positions from the header row and slice each data row at those positions. This is a significant new feature (~200 LOC new module) -- essentially a text-mode table parser that runs as a fallback when no HTML tables match. Low priority because pre-2014 BDC filings pre-date XBRL entirely and are out of scope for the post-2019 index. Affects Princeton Capital Corp 5 filings (2013); likely pattern in other small pre-modernization BDC filers.

22. **[IMPLEMENTED] `_select_best_variant()` / `find_schedule_tables()` -- minimum-row and numeric-content thresholds for schedule candidates.** `find_schedule_tables()` currently accepts any table whose headers partially match template column names, even when the table has only 1-5 rows and zero parseable dollar values. Small non-schedule tables (highlights summaries, NAV rollforwards, single-line cover-page references) with shape-matching headers get selected when the actual schedule is absent or uses a non-standard format. Example: Princeton Capital Corp (CIK 845385) 2015 filing `0001213900-15-002764` extracts 5 holdings with 0 FV -- the engine picks a small table whose rows are partially schedule-like but whose financial cells don't parse. Amendment #20's content-rejection catches the highlights case; this amendment catches small malformed tables that aren't highlights either. Fix: enforce minimum thresholds in candidate ranking -- at least 5 data rows, at least one cell parseable as a dollar value >$100K, at least one column with predominantly numeric values (>50% of non-empty cells parse as numbers). When no candidate meets these thresholds, return empty and log "no schedule found" rather than accepting a degenerate match. Combined with amendment #21, would cleanly separate extractable filings from unextractable ones rather than producing 0-FV drift extractions. Low risk -- legitimate schedules always exceed these thresholds. Affects Princeton Capital Corp 1 filing (2015-04); would also benefit other filers where the engine currently false-matches due to missing/malformed schedules.

Implemented in Wave 3. `_has_significant_content()` rejects tables with <5 data rows AND no cell >$100K. Files: `pipeline/html_holdings.py`.

23. **[IMPLEMENTED] `post_process()` (html_holdings.py) -- industry propagation to continuation rows.** The `post_process()` function in `pipeline/html_holdings.py` (line 646-650) propagates only `issuer_name` from a new position row to its continuation rows. It does NOT propagate the `industry` field even though industry is equally sticky per holding. When a filer has a separate Industry column plus multi-row positions (company and industry only appear on row 1, continuation rows have only instrument/financials), the engine leaves industry null on every continuation row. Fix: extend the existing `issuer_name` propagation loop to also copy `industry` from the prior new-position row when the current row is a continuation (has `_is_continuation=True` or equivalent marker). Also consider propagating other stable per-holding fields (affiliation, footnote_refs) by the same mechanism. Affects Gladstone Investment Corporation (CIK 1321741) 6-col variant (19 filings, 2013-2017): industry fill 44% instead of ~100% -- continuation rows account for ~55% of all data rows and all have empty industry despite the filer clearly grouping them under a single Industry column cell. Likely affects any v1.0/v2.0 filer with a separate Industry column and multi-row position structure (e.g., older Main Street Capital, Oaktree Specialty Lending 2013-2015 eras). Low risk -- industry on a continuation row is definitionally the same as the preceding new-position row since continuations belong to the same holding.

Implemented in Wave 2. `post_process()` now propagates `industry` from new-position rows to continuation rows alongside issuer_name. Files: `pipeline/html_holdings.py`.

24. **[IMPLEMENTED] `_apply_template_column_map()` -- `instrument_in_company_cell` em-dash / dash separator support.** When `filer_quirks.instrument_in_company_cell: true` is set, the engine at `pipeline/html_template.py` line 572-578 only splits the company cell on `\n` (newline) to separate company from instrument description. Filers that put company and instrument in the same cell on a single line using an em-dash (U+2013 "--"), en-dash, or hyphen separator (e.g., "Drew Foam Companies, Inc. -- Term Debt (13.5%, Due 6/30/2021)") leave `instrument_description` empty and the full "Company -- Instrument" string in `issuer_name`. Fix: add a configurable `instrument_separator` field to `filer_quirks` (e.g., `"instrument_separator": "em_dash"` or a literal string like `" -- "`) that the engine uses alongside `\n` for splitting. Fall back to splitting on the first of `\n`, em-dash (U+2013), en-dash (U+2014), or " - " when present. The split should preserve punctuation-inclusive company names (e.g., "Acme, Inc." should not be truncated at the comma). Affects Gladstone Investment Corporation (CIK 1321741) 4-col variant (20 filings, 2017-2022): all ~3,910 holdings have empty `investment_type` despite clean "Company -- Instrument" format. Likely affects other small/mid-size BDCs that consolidated multi-column schedules into a single "Company and Investment" column over time. Low risk -- the separator is unambiguous in the SEC HTML and only activates when the template explicitly opts in via `instrument_in_company_cell: true`.

Implemented in Wave 2. When `instrument_in_company_cell` and no newline split found, tries em-dash (U+2013), en-dash (U+2014), and ' -- ' separators. Files: `pipeline/html_template.py`.

25. **[IMPLEMENTED, LOW IMPACT] `_select_best_variant()` -- filing-date-aware variant tiebreaker.** When two variants produce identical header-scoring tuples `(real, shift, skip, col_delta, -gp_overlap)`, the filing date is used as a final tiebreaker. A variant whose `[effective_from, effective_until)` date window contains the filing date wins the tie over one that does not. Date windows are auto-derived from each variant's `source_filing` accession number via `bdc_filings_index.csv` (earliest variant is open on the left; latest is open on the right; boundaries are exclusive on the right). Templates may also declare explicit `effective_from` / `effective_until` fields per variant to override auto-derivation. **Critical design choice**: date is the LAST tiebreaker, not a pre-filter. A more aggressive pre-filter version was tested and caused severe regressions (e.g., PhenixFIN CIK 1490349 dropped from 32 non-empty filings to 16 because 10-K and 10-Q filings use different variants concurrently -- the 10-K "2013_8col_embedded_rate" variant had its `source_filing` from 2013 so a strict date filter excluded it from all 2015+ filings, but header scoring clearly distinguishes 10-K from 10-Q in every post-2015 filing). As implemented, the tiebreaker: (a) has zero regressions across all 968 baseline filings (0 variant changes with row loss); (b) activates rarely because header scoring usually produces a strict winner; (c) does not fix the CION (CIK 1534254) 2020-08+ or Oaktree (CIK 1414932) 2020+ empty-extraction cases, because those filings' HTML grid spacing changed and no variant matches well (the legacy variant wins on `shift` count, which happens before the date tiebreaker). Those cases require engine amendment #14 (adaptive grid-position shifting) or template updates with new variants. Tests: 9 new in `tests/test_html_template.py::TestVariantDateRanges`.
