- securitisation tranche: `^[A-Z0-9]+ (?:(?:19|20)\d\d-[A-Z0-9]+|\d+X) [A-Z0-9]+$` (e.g. "BMARK 2025-B41 JRR",

  158,378 / 283,782 / 332,797 / 235,736; page CMBS + RMBS + IO + CLO at 2026-03-31 = 236,839, the
  difference 1,103 is "EURO 41X E".
- corporate bond or syndicated loan: `^[A-Z]+ .*(?:\d\d/\d{4}|\d\.\d+ 20\d\d|FRN)` matches 1 / 1 / 6 / 3 rows =
  1,290 / 1,288 / 18,959 / 30,171 (2026-03-31: BAYCLU 18,714 + CPKLN 10,391 + SERVAT 1,066).
- everything else (24 / 26 / 33 / 39 rows, 340,418 / 508,283 / 1,176,561 / 1,689,496) is a property or
  portfolio name = a real-estate loan or note (senior, mezzanine, credit-linked note).
The patterns cannot tell CMBS from RMBS from CLO, nor senior from mezzanine; only the printed section does.

Whether these rows belong in a private-credit loan class: the 1.69B of property loans are privately
originated loans but secured on real estate (the page calls them "Investments in loans"); 236.8M are
traded structured securities and 11.5M bonds. Publishing all of it as DIRECT_LENDING overstates direct
lending by the whole fund. This is a classification decision for the owner, not a tagging error.
